# 问卷系统数据库设计文档（DAG 存储方案）

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 编写日期 | 2026-10-15 |
| 适用数据库 | PostgreSQL 14+ |
| 存储核心 | 有向无环图（DAG），邻接表 + 模板/实例双套快照隔离 |

---

## 1. 文档说明

本文档描述问卷系统的数据库设计，重点解决两个核心问题：

1. **问卷模板如何用 DAG 存储**：模板本质是一类核查任务的通用问卷结构（题目节点 + 分支跳转边），天然是有向无环图。
2. **模板与下发实例如何解耦**：下发时从模板复制出独立快照，草稿期可临时修改结构，修改不回写原模板；支持显式"另存为新模板 / 更新原模板"。

覆盖范围：模板分类、模板 DAG、实例 DAG、核查任务、答卷、答卷明细、答题轨迹，共 11 张表。

---

## 2. 业务背景与设计目标

### 2.1 业务场景

- 模板库中存在多类通用模板，如「无人机核查问卷」「人员兴趣爱好调查问卷」，每类对应一种核查任务。
- **高频操作**：选择某类任务的通用模板 → 填写下发信息 → 下发问卷实例。
- **低频操作**：下发前临时调整问卷结构（如给特殊核查对象临时增加「国籍」题目），调整只作用于本次下发的实例，**不覆盖**通用模板；如需沉淀，可显式"另存为新模板"或"覆盖原模板"。
- 问卷实例下发后，答题端需要按 DAG 分支逻辑渲染题目、做跳转。

### 2.2 设计目标

| 目标 | 说明 |
|---|---|
| 模板长期稳定 | 通用模板是基准，只在后台显式编辑时变更 |
| 实例结构隔离 | 每个实例是独立 DAG 快照，下发后结构冻结，不受模板后续改版影响 |
| 分支语义正确 | DAG 有方向、无环、允许多父（一个题目可被多个题目跳转而来） |
| 可追溯 | 实例记录来源模板及版本；节点/边记录来源模板节点/边 |
| 读写平衡 | 模板几乎不写；实例草稿编辑期有写、下发后只读；答卷高频插入 |

### 2.3 术语定义

| 术语 | 含义 |
|---|---|
| 模板（Template） | 一类任务的通用问卷基准，由模板 DAG 描述，常驻模板库 |
| 模板 DAG | `template_node`（题目/分组/结束节点）+ `template_edge`（分支跳转边） |
| 实例（Instance） | 从模板复制出的独立问卷，承载一次具体下发；草稿可改结构，下发后冻结 |
| 实例 DAG | `instance_node` + `instance_edge`，与模板 DAG 物理隔离 |
| 草稿态（draft） | 已复制但未下发，结构可编辑 |
| 下发态（published） | 已下发，结构锁定，答题端可作答 |
| 完成态（finished） | 问卷回收完成（实例级别状态，可扩展） |

## 3. 核心设计思路

### 3.1 为什么用"邻接表 + 双套快照"而不是其他方案

| 候选方案 | 结论 | 原因 |
|---|---|---|
| 邻接表 + 递归 CTE（采用） | ✅ 采用 | 单份问卷节点量级小（几十题），递归遍历足够快；实现简单，环校验可控 |
| 传递闭包表 | ❌ 排除 | 维护成本高；模板→实例复制时还要同步复制闭包；问卷场景读路径单次量小，收益低 |
| ltree 扩展 | ❌ 排除 | ltree 只适合单父树；问卷分支天然多父（一题被多题跳转），是 DAG 不是树 |
| Apache AGE 图插件 | ❌ 排除 | 重型依赖，多数云 PG 不开放；业务是"小图多副本"而非海量图分析 |
| 模板 + 增量 diff 补丁 | ❌ 排除 | DAG 的 diff（增节点、删边、改条件）合并、环校验、渲染都要自研一套，模板改版后 diff 易失效；快照复制成本可忽略且工程最稳 |

### 3.2 模板 / 实例双套表隔离

- 模板侧：`template_node` / `template_edge` —— 只读基准，后台编辑。
- 实例侧：`instance_node` / `instance_edge` —— 每次下发复制一份，草稿期可改。
- 铁则：**已下发的实例结构永远稳定，与模板后续改版无关**。

### 3.3 关键流程一句话

> 选择模板 →（事务内）创建草稿实例并全量复制 DAG（维护节点 id 映射）→ 可选编辑实例 DAG → 下发（状态冻结）；如需沉淀改动，显式执行"另存为新模板 / 更新原模板"。

## 4. 数据模型总览

### 4.1 实体关系（ER）

```
questionnaire_template_category 1 ── N questionnaire_template
questionnaire_template          1 ── N template_node
questionnaire_template          1 ── N template_edge
questionnaire_template          1 ── N questionnaire_instance（溯源）
questionnaire_instance          1 ── N instance_node
questionnaire_instance          1 ── N instance_edge
questionnaire_instance       1 ─ 0..1 inspection_task（核查任务）
questionnaire_instance          1 ── N questionnaire_answer（答卷）
questionnaire_answer            1 ── N questionnaire_answer_detail（答卷明细）
questionnaire_answer            1 ── N answer_trace（答题轨迹，可选）
```

### 4.2 分层说明

| 分层 | 表 | 说明 |
|---|---|---|
| 模板层 | category / template / template_node / template_edge | 通用基准，后台维护 |
| 实例层 | instance / instance_node / instance_edge | 每次下发的独立快照 |
| 任务层 | inspection_task | 一次核查任务的业务信息（与实例 1:1） |
| 答卷层 | answer / answer_detail / answer_trace | 答题人填写的完整数据 |

## 5. 表结构详细设计

> 命名规范：表名单数小写下划线；字段 snake_case；时间统一 `TIMESTAMPTZ`；金额/计分用数值类型；动态结构用 `JSONB`。

### 5.1 questionnaire_template_category —— 模板分类表

**用途**：对应不同核查任务种类（无人机核查、人员兴趣调查……）。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 主键 |
| category_code | VARCHAR(64) | UNIQUE NOT NULL | 分类编码，如 `drone_check` |
| category_name | TEXT | NOT NULL | 分类名称 |
| description | TEXT | | 描述 |
| created_at | TIMESTAMPTZ | DEFAULT now() | 创建时间 |

```sql
CREATE TABLE questionnaire_template_category (
    id            BIGSERIAL PRIMARY KEY,
    category_code VARCHAR(64)  NOT NULL UNIQUE,
    category_name TEXT         NOT NULL,
    description   TEXT,
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);
```

### 5.2 questionnaire_template —— 通用模板主表

**用途**：一类任务唯一在用的通用模板；支持版本迭代（`version` 自增）。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 主键 |
| category_id | BIGINT | FK → category(id) | 所属分类 |
| template_name | TEXT | NOT NULL | 模板名称 |
| version | INT | NOT NULL DEFAULT 1 | 版本号，覆盖更新时 +1 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'active' | active / disabled |
| remark | TEXT | | 备注 |
| created_at | TIMESTAMPTZ | DEFAULT now() | 创建时间 |
| updated_at | TIMESTAMPTZ | DEFAULT now() | 更新时间 |

```sql
CREATE TABLE questionnaire_template (
    id            BIGSERIAL PRIMARY KEY,
    category_id   BIGINT      NOT NULL REFERENCES questionnaire_template_category(id),
    template_name TEXT        NOT NULL,
    version       INT         NOT NULL DEFAULT 1,
    status        VARCHAR(16) NOT NULL DEFAULT 'active',
    remark        TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (category_id, version)
);
CREATE INDEX idx_template_category ON questionnaire_template(category_id);
```

### 5.3 template_node —— 模板 DAG 节点表

**用途**：模板内的题目 / 分组 / 结束节点。节点配置（题干、选项、控件类型、校验规则）整体放入 `config JSONB`，适配问卷控件多样、schema 不稳定。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 节点 ID（模板域内） |
| template_id | BIGINT | FK → template(id) ON DELETE CASCADE | 所属模板 |
| node_type | VARCHAR(32) | NOT NULL | question / group / end |
| title | TEXT | | 题目或分组标题 |
| config | JSONB | NOT NULL | 题干、选项、控件、必填、校验规则 |
| sort_no | INT | NOT NULL DEFAULT 0 | 同级排序 |
| created_at | TIMESTAMPTZ | DEFAULT now() | 创建时间 |

```sql
CREATE TABLE template_node (
    id          BIGSERIAL PRIMARY KEY,
    template_id BIGINT      NOT NULL REFERENCES questionnaire_template(id) ON DELETE CASCADE,
    node_type   VARCHAR(32) NOT NULL,
    title       TEXT,
    config      JSONB       NOT NULL,
    sort_no     INT         NOT NULL DEFAULT 0,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_tpl_node_tpl ON template_node(template_id);
```

`config` 示例（示意数据）：

```json
{
  "question_type": "single_choice",
  "text": "核查对象的国籍是？",
  "options": [
    { "option_id": "o1", "label": "中国" },
    { "option_id": "o2", "label": "其他" }
  ],
  "required": true,
  "validators": []
}
```

### 5.4 template_edge —— 模板 DAG 边表

**用途**：分支跳转关系，`from_node` 满足 `condition` 后流向 `to_node`。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 主键 |
| template_id | BIGINT | FK → template(id) ON DELETE CASCADE | 所属模板（冗余便于按模板整体删除/复制） |
| from_node | BIGINT | NOT NULL，引用 template_node(id) | 起点节点 |
| to_node | BIGINT | NOT NULL，引用 template_node(id) | 终点节点 |
| condition | JSONB | | 分支条件，如 `{"option_id":"o1"}` |
| created_at | TIMESTAMPTZ | DEFAULT now() | 创建时间 |

约束：
- `UNIQUE(template_id, from_node, to_node, condition)`：防止重复边。
- `CHECK (from_node <> to_node)`：禁止自环。

```sql
CREATE TABLE template_edge (
    id          BIGSERIAL PRIMARY KEY,
    template_id BIGINT NOT NULL REFERENCES questionnaire_template(id) ON DELETE CASCADE,
    from_node   BIGINT NOT NULL,
    to_node     BIGINT NOT NULL,
    condition   JSONB,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (template_id, from_node, to_node, condition),
    CHECK (from_node <> to_node)
);
CREATE INDEX idx_tpl_edge_tpl  ON template_edge(template_id);
CREATE INDEX idx_tpl_edge_from ON template_edge(from_node);
CREATE INDEX idx_tpl_edge_to   ON template_edge(to_node);
```

### 5.5 questionnaire_instance —— 问卷实例主表

**用途**：一次下发对应的问卷快照载体；记录来源模板与状态。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 实例 ID |
| template_id | BIGINT | NOT NULL → template(id) | 来源模板（溯源） |
| template_version | INT | NOT NULL | 来源模板版本快照（溯源更稳） |
| instance_no | VARCHAR(64) | UNIQUE NOT NULL | 实例编号，如 `INS-20261015-0001` |
| status | VARCHAR(16) | NOT NULL DEFAULT 'draft' | draft / published / finished |
| is_modify_template_snapshot | BOOLEAN | NOT NULL DEFAULT false | 是否在模板基础上改过结构（统计/展示用） |
| created_at | TIMESTAMPTZ | DEFAULT now() | 创建时间 |
| published_at | TIMESTAMPTZ | | 下发时间 |

```sql
CREATE TABLE questionnaire_instance (
    id                          BIGSERIAL PRIMARY KEY,
    template_id                 BIGINT      NOT NULL REFERENCES questionnaire_template(id),
    template_version            INT         NOT NULL,
    instance_no                 VARCHAR(64) NOT NULL UNIQUE,
    status                      VARCHAR(16) NOT NULL DEFAULT 'draft',
    is_modify_template_snapshot BOOLEAN     NOT NULL DEFAULT false,
    created_at                  TIMESTAMPTZ NOT NULL DEFAULT now(),
    published_at                TIMESTAMPTZ
);
CREATE INDEX idx_instance_template ON questionnaire_instance(template_id);
CREATE INDEX idx_instance_status   ON questionnaire_instance(status);
```

### 5.6 instance_node —— 实例 DAG 节点表

**用途**：实例内题目/分组/结束节点，独立自增主键；记录来源模板节点（溯源）。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 节点 ID（实例域内） |
| instance_id | BIGINT | FK → instance(id) ON DELETE CASCADE | 所属实例 |
| source_template_node_id | BIGINT | NULL 可 | 来源模板节点；草稿期新增节点为 NULL |
| node_type | VARCHAR(32) | NOT NULL | question / group / end |
| title | TEXT | | 标题 |
| config | JSONB | NOT NULL | 与 template_node.config 同构 |
| sort_no | INT | NOT NULL DEFAULT 0 | 排序 |
| created_at | TIMESTAMPTZ | DEFAULT now() | 创建时间 |

```sql
CREATE TABLE instance_node (
    id                      BIGSERIAL PRIMARY KEY,
    instance_id             BIGINT      NOT NULL REFERENCES questionnaire_instance(id) ON DELETE CASCADE,
    source_template_node_id BIGINT,
    node_type               VARCHAR(32) NOT NULL,
    title                   TEXT,
    config                  JSONB       NOT NULL,
    sort_no                 INT         NOT NULL DEFAULT 0,
    created_at              TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_inst_node_inst ON instance_node(instance_id);
```

### 5.7 instance_edge —— 实例 DAG 边表

**用途**：实例内分支跳转边；草稿期新增/修改的边 `source_template_edge_id = NULL`。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 主键 |
| instance_id | BIGINT | FK → instance(id) ON DELETE CASCADE | 所属实例 |
| source_template_edge_id | BIGINT | NULL 可 | 来源模板边（溯源） |
| from_node | BIGINT | NOT NULL，引用 instance_node(id) | 起点 |
| to_node | BIGINT | NOT NULL，引用 instance_node(id) | 终点 |
| condition | JSONB | | 分支条件 |

约束：`UNIQUE(instance_id, from_node, to_node, condition)`、`CHECK (from_node <> to_node)`。

```sql
CREATE TABLE instance_edge (
    id                      BIGSERIAL PRIMARY KEY,
    instance_id             BIGINT NOT NULL REFERENCES questionnaire_instance(id) ON DELETE CASCADE,
    source_template_edge_id BIGINT,
    from_node               BIGINT NOT NULL,
    to_node                 BIGINT NOT NULL,
    condition               JSONB,
    UNIQUE (instance_id, from_node, to_node, condition),
    CHECK (from_node <> to_node)
);
CREATE INDEX idx_inst_edge_inst ON instance_edge(instance_id);
CREATE INDEX idx_inst_edge_from ON instance_edge(from_node);
CREATE INDEX idx_inst_edge_to   ON instance_edge(to_node);
```

### 5.8 inspection_task —— 核查任务表

**用途**：一次核查任务的业务信息（核查对象、时间、执行人），与实例 1:1。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 主键 |
| instance_id | BIGINT | UNIQUE NOT NULL → instance(id) | 关联实例（1:1） |
| task_no | VARCHAR(64) | UNIQUE NOT NULL | 任务编号 |
| object_name | TEXT | NOT NULL | 核查对象（如无人机编号/被调查人） |
| inspector | TEXT | | 核查人 |
| plan_time | TIMESTAMPTZ | | 计划核查时间 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'pending' | pending / doing / done |
| remark | TEXT | | 备注 |
| created_at | TIMESTAMPTZ | DEFAULT now() | 创建时间 |

```sql
CREATE TABLE inspection_task (
    id          BIGSERIAL PRIMARY KEY,
    instance_id BIGINT      NOT NULL UNIQUE REFERENCES questionnaire_instance(id),
    task_no     VARCHAR(64) NOT NULL UNIQUE,
    object_name TEXT        NOT NULL,
    inspector   TEXT,
    plan_time   TIMESTAMPTZ,
    status      VARCHAR(16) NOT NULL DEFAULT 'pending',
    remark      TEXT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_task_status ON inspection_task(status);
```

> 若后续一个实例可能对应多任务，将 `instance_id` 的唯一约束去掉改为普通外键即可，设计上保留扩展空间。

### 5.9 questionnaire_answer —— 答卷主表

**用途**：一次作答记录（一个人对一份实例问卷的一次填写）。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 答卷 ID |
| instance_id | BIGINT | NOT NULL → instance(id) | 关联实例（**只绑实例，不绑模板**，保证历史答卷与下发时结构一致） |
| respondent_type | VARCHAR(16) | NOT NULL | 答题人类型：person / device / org |
| respondent_no | VARCHAR(64) | NOT NULL | 答题人编号（脱敏存储） |
| status | VARCHAR(16) | NOT NULL DEFAULT 'draft' | draft / submitted |
| score | NUMERIC(10,2) | | 总分（如有计分） |
| submit_at | TIMESTAMPTZ | | 提交时间 |
| created_at | TIMESTAMPTZ | DEFAULT now() | 创建时间 |

```sql
CREATE TABLE questionnaire_answer (
    id              BIGSERIAL PRIMARY KEY,
    instance_id     BIGINT       NOT NULL REFERENCES questionnaire_instance(id),
    respondent_type VARCHAR(16)  NOT NULL,
    respondent_no   VARCHAR(64)  NOT NULL,
    status          VARCHAR(16)  NOT NULL DEFAULT 'draft',
    score           NUMERIC(10,2),
    submit_at       TIMESTAMPTZ,
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (instance_id, respondent_type, respondent_no)
);
CREATE INDEX idx_answer_instance ON questionnaire_answer(instance_id);
CREATE INDEX idx_answer_status   ON questionnaire_answer(status);
```

### 5.10 questionnaire_answer_detail —— 答卷明细表

**用途**：每道题的作答结果，绑定**实例节点**（而非模板节点），与下发时结构一一对应。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 明细 ID |
| answer_id | BIGINT | FK → answer(id) ON DELETE CASCADE | 所属答卷 |
| instance_node_id | BIGINT | NOT NULL → instance_node(id) | 对应实例题目节点 |
| node_type | VARCHAR(32) | NOT NULL | question / group（group 可记录到达/跳过） |
| question_key | VARCHAR(64) | | 题目标识（冗余自模板，便于报表） |
| answer_value | JSONB | | 答案：单选/多选/文本/日期等 |
| answered_at | TIMESTAMPTZ | | 作答时间 |

```sql
CREATE TABLE questionnaire_answer_detail (
    id               BIGSERIAL PRIMARY KEY,
    answer_id        BIGINT      NOT NULL REFERENCES questionnaire_answer(id) ON DELETE CASCADE,
    instance_node_id BIGINT      NOT NULL REFERENCES instance_node(id),
    node_type        VARCHAR(32) NOT NULL,
    question_key     VARCHAR(64),
    answer_value     JSONB,
    answered_at      TIMESTAMPTZ
);
CREATE INDEX idx_ans_detail_answer ON questionnaire_answer_detail(answer_id);
CREATE INDEX idx_ans_detail_node   ON questionnaire_answer_detail(instance_node_id);
```

`answer_value` 示例：

```json
{ "option_ids": ["o1"], "text": null }
```

### 5.11 answer_trace —— 答题轨迹表（可选）

**用途**：记录作答过程中每个节点的进入/跳过/跳转，用于回放、审计、分支规则调优。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | 主键 |
| answer_id | BIGINT | FK → answer(id) ON DELETE CASCADE | 所属答卷 |
| instance_node_id | BIGINT | NOT NULL | 当前节点 |
| action | VARCHAR(16) | NOT NULL | enter / skip / jump |
| next_node_id | BIGINT | | 跳转目标（action=jump 时） |
| trigger_at | TIMESTAMPTZ | DEFAULT now() | 发生时间 |

```sql
CREATE TABLE answer_trace (
    id               BIGSERIAL PRIMARY KEY,
    answer_id        BIGINT      NOT NULL REFERENCES questionnaire_answer(id) ON DELETE CASCADE,
    instance_node_id BIGINT      NOT NULL,
    action           VARCHAR(16) NOT NULL,
    next_node_id     BIGINT,
    trigger_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_trace_answer ON answer_trace(answer_id);
```

## 6. 索引与约束汇总

| 关注点 | 设计 |
|---|---|
| 边表唯一 | `UNIQUE(template_id / instance_id, from_node, to_node, condition)` 防重复边 |
| 防自环 | `CHECK (from_node <> to_node)` |
| 防环（业务级） | DAG 环检测逻辑在保存/下发前通过递归 CTE 校验（数据库无原生 DAG 约束） |
| 遍历加速 | 边表 `from_node` / `to_node` 双向索引 |
| 快照复制加速 | 模板节点/边按 `template_id` 批量查询 |
| 溯源 | 实例节点/边保留 `source_template_*_id`；实例记录 `template_id + template_version` |
| 答卷稳定 | 答卷只关联实例，明细只关联实例节点 |

## 7. DAG 核心操作

### 7.1 从模板复制生成草稿实例（事务内，维护节点 id 映射）

**这是整个设计的核心操作**：模板节点 ID 与实例节点 ID 是两套独立自增，复制边时必须把模板边上的 `from_node / to_node` 替换为对应的实例节点 ID。

```sql
-- 伪 SQL 流程（可在存储过程或应用层事务中执行）
BEGIN;

-- 1. 创建草稿实例
INSERT INTO questionnaire_instance (template_id, template_version, instance_no, status)
VALUES (1, 1, 'INS-20261015-0001', 'draft')
RETURNING id;  -- 得到 v_inst_id

-- 2. 复制节点，建立 模板节点id -> 实例节点id 映射
CREATE TEMP TABLE node_map (tpl_node_id BIGINT, inst_node_id BIGINT) ON COMMIT DROP;

INSERT INTO instance_node (instance_id, source_template_node_id, node_type, title, config, sort_no)
SELECT v_inst_id, id, node_type, title, config, sort_no
FROM template_node
WHERE template_id = 1
RETURNING source_template_node_id, id INTO node_map;

-- 3. 复制边：替换节点 id
INSERT INTO instance_edge (instance_id, source_template_edge_id, from_node, to_node, condition)
SELECT v_inst_id, e.id, m1.inst_node_id, m2.inst_node_id, e.condition
FROM template_edge e
JOIN node_map m1 ON m1.tpl_node_id = e.from_node
JOIN node_map m2 ON m2.tpl_node_id = e.to_node
WHERE e.template_id = 1;

COMMIT;
```

> 应用层（如 Node.js）中，`node_map` 用临时表或内存 Map 均可；关键是不能直接复用节点 id。

### 7.2 遍历下游（所有后继节点，递归 CTE）

```sql
WITH RECURSIVE dag_down AS (
    SELECT from_node, to_node, 1 AS depth
    FROM instance_edge
    WHERE instance_id = 1 AND from_node = 10   -- 起点节点
    UNION ALL
    SELECT e.from_node, e.to_node, dd.depth + 1
    FROM instance_edge e
    JOIN dag_down dd ON e.from_node = dd.to_node
    WHERE e.instance_id = 1
)
SELECT DISTINCT to_node, depth FROM dag_down;
```

### 7.3 遍历上游（所有前置节点）

```sql
WITH RECURSIVE dag_up AS (
    SELECT from_node, to_node, 1 AS depth
    FROM instance_edge
    WHERE instance_id = 1 AND to_node = 10
    UNION ALL
    SELECT e.from_node, e.to_node, du.depth + 1
    FROM instance_edge e
    JOIN dag_up du ON e.to_node = du.from_node
    WHERE e.instance_id = 1
)
SELECT DISTINCT from_node, depth FROM dag_up;
```

### 7.4 环检测（保存结构 / 下发前必做）

以"新增一条边 A→B 是否会成环"为例（`instance_edge` 同理）：

```sql
-- 假设要插入 from=20 → to=10，检查 20 现有下游中是否存在 10
WITH RECURSIVE check_cycle AS (
    SELECT to_node
    FROM instance_edge
    WHERE instance_id = 1 AND from_node = 20
    UNION ALL
    SELECT e.to_node
    FROM instance_edge e
    JOIN check_cycle cc ON e.from_node = cc.to_node
    WHERE e.instance_id = 1
)
SELECT EXISTS (SELECT 1 FROM check_cycle WHERE to_node = 10) AS would_cycle;
-- true：会成环，禁止插入
```

> 模板 DAG 在模板保存时校验；实例 DAG 在草稿每次保存、下发前校验。**校验与写操作必须在同一事务内**，防止并发插入产生"幻环"。

### 7.5 渲染问卷（按实例输出有序结构）

```sql
SELECT n.id, n.node_type, n.title, n.config,
       COALESCE(
         jsonb_agg(
           jsonb_build_object('to', e.to_node, 'condition', e.condition)
           ORDER BY e.id
         ) FILTER (WHERE e.id IS NOT NULL),
         '[]'::jsonb
       ) AS out_edges
FROM instance_node n
LEFT JOIN instance_edge e ON e.instance_id = n.instance_id AND e.from_node = n.id
WHERE n.instance_id = 1
GROUP BY n.id
ORDER BY n.sort_no, n.id;
```

答题端拿到每个节点的出边（含条件），本地做分支跳转即可。

### 7.6 拓扑排序

推荐在**应用层用 Kahn 算法**实现（统计入度 → 不断取入度为 0 的节点 → 减少后继入度），不在数据库内频繁执行；数据量小也可用递归 CTE 自底向上推导。

## 8. 关键业务流程

### 8.1 下发流程（高频）

```
选择模板（template_id）
  → 事务：建 instance(draft) + 复制 node/edge（节点 id 映射）
  → 页面展示草稿，填写任务信息
  → （可选）编辑草稿 DAG：增删题目、改跳转分支 —— 只动 instance_* 表
  → 点击【下发】：环校验 → status: draft → published，结构冻结
```

### 8.2 模板沉淀流程（低频，显式操作）

| 操作 | 行为 |
|---|---|
| 【另存为新模板】 | 把当前实例 DAG 复制成新 template（新分类或同名新模板），版本从 1 开始 |
| 【更新原模板】 | 用当前实例 DAG 覆盖原 template，version + 1；需强二次确认 |

两个按钮必须严格语义隔离，避免运营误操作覆盖通用模板。

### 8.3 实例状态机

```
draft ──下发──▶ published ──回收/关闭──▶ finished
  │
  └──取消──▶ （删除/归档，业务自定义）
```

## 9. 事务与并发设计

| 场景 | 要求 |
|---|---|
| 复制模板 → 实例 | 单事务原子完成；失败整体回滚 |
| 草稿保存结构 | `DELETE instance_edge/node + INSERT 新结构 + 环校验` 同一事务 |
| 环检测 + 插入边 | 同一事务，串行化或行锁防并发幻环；高并发下可对 `instance_id` 加 `SELECT ... FOR UPDATE` |
| 模板覆盖更新 | 旧模板 node/edge 删除 + 新结构写入 + version+1 同一事务 |
| 答卷提交 | `answer + answer_detail` 批量插入同一事务 |

---

## 10. 注意事项与边界

1. **PG 无原生 DAG 约束**：防环必须业务实现，模板保存、草稿保存、下发三个时机校验。
2. **实例结构永久稳定**：答卷明细只关联 `instance_node_id`，绝不关联模板节点。
3. **模板版本策略**：实例记录 `template_version`；模板改版后老实例不受影响，新下发用新版。
4. **性能评估**：单份问卷节点量级 ≤ 数百，递归 CTE 毫秒级；全量快照复制成本可忽略。若未来出现万级节点的大图，再评估闭包表或图存储。
5. **JSONB 取舍**：节点 `config`、答案 `answer_value` 用 JSONB 换取灵活性；如需对答案做复杂统计，可另建宽表/物化视图。
6. **数据脱敏**：答题人字段建议脱敏存储，符合个人信息保护要求。
7. **分表扩展**：答卷量级大时按 `instance_id` 或时间分区；明细表可按 `answer_id` 分区。
